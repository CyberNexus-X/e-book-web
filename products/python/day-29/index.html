Day 29 — pip aur virtual env

pip Python ke packages install karta hai, venv har project ka alag environment banata hai taaki versions clash na hon. Ye din code nahi, terminal commands ka hai.

Phase: Intermediate · Reels: 141/450 – 145/450

Code

python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate
pip install requests
pip freeze > requirements.txt
pip install -r requirements.txt
deactivate

Output

Ye din terminal commands ka hai, isliye koi Python output nahi hai. Commands ko apne computer ke terminal me order se chalao.

Code ki poori detail

  • python -m venv .venv — project ke andar .venv naam ka alag environment banata hai.
  • source .venv/bin/activate (Mac/Linux) ya .venv\Scripts\activate (Windows) — environment ko on karta hai.
  • pip install requests — requests package sirf isi environment me install hota hai, global me nahi.
  • pip freeze > requirements.txt — installed packages aur versions ki list file me save karta hai.
  • pip install -r requirements.txt — kisi bhi naye PC par wahi setup dobara bana deta hai.
  • deactivate — environment ko band kar deta hai.
Common mistake: Har package global install karna projects ke versions clash karwata hai. Har project ka apna venv banao.
Khud try karo: Apne project ke liye venv banao, ek package install karo aur requirements.txt banao.
